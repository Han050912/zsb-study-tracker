## 核心增强一：富媒体发帖与图片上传

> 设计参考：Stack Overflow 的拖拽上传 + 粘贴上传、Discourse 的图文混排编辑器、Apache Answer 的 Markdown 编辑器。
> 技术方案：利用项目已有的 Cloudflare Worker 基础设施，图片存储使用 Cloudflare R2（零出口费），前端使用浏览器 File API 实现拖拽/粘贴上传。

### 设计目标

让用户在社区发帖时能够上传图片，**大幅降低答疑沟通成本**（"一道题说不清楚？截图上传，大家帮你分析"），同时吸引更多用户因为"能贴图讨论题目"而使用社区。

| 功能名称 | 描述 | 优先级 | 实现状态 |
|---------|------|--------|---------|
| 图片上传基础能力 | 发帖编辑器支持插入图片。用户可通过点击上传按钮、拖拽文件到编辑区、或 Ctrl+V 粘贴剪贴板图片三种方式添加图片。图片自动上传至 Cloudflare R2 并返回 URL 嵌入内容中。 | **P0** | **【已实现】** 前端 `PostComposer` 支持三通道上传 + XHR 进度条 + 上传失败重试/移除；worker `uploads.ts` 实现上传与公开代理读取路由 `/api/community/images/:id`（不可枚举 id + immutable 长缓存） |
| 图片上传限制与安全 | 单张最大 5MB，单帖最多 9 张。支持格式：PNG / JPEG / WebP / GIF。服务端校验文件类型（Magic Bytes 校验，防止伪造 Content-Type），自动去除 EXIF 元数据（隐私保护）。超出限制时前端即时提示，不浪费上传带宽。 | **P0** | **【已实现】** 前后端双重大小/数量校验；Magic Bytes 嗅探真实格式；服务端剥离 JPEG APP1/COM 段、PNG eXIf/文本块、WebP EXIF/XMP 块；限流 20 次/分 |
| 图片展示与预览 | 帖子详情中图片自适应宽度展示，支持点击放大（Lightbox 灯箱预览）。列表卡片中最多展示首张图片缩略图（16:9 裁剪），避免列表页加载过重。 | **P0** | **【已实现】** 列表首图 16:9 缩略 + 张数角标；详情 1/2/3 列网格 + `Lightbox` 灯箱（左右切换/Esc 关闭） |
| Markdown 编辑器（扩展） | 现有纯文本 textarea 升级为轻量 Markdown 编辑器（复用项目已有 `markdown-it` 依赖）。支持粗体、行内代码、代码块、引用、列表、LaTeX 数学公式（复用已有 `katex` 依赖）。图片上传与 Markdown 编辑器无缝集成：上传后自动插入 `![](url)` 语法。 | P1 | **【已实现】** 复用项目既有 `renderMarkdown`（markdown-it + KaTeX + 防 XSS）：PostComposer 新增 Markdown 工具栏（粗体/行内代码/代码块/引用/列表/行内与块级公式）+ 编辑/预览 Tab 切换；帖子详情页富文本渲染，列表页保持纯文本截断预览。**差异说明**：图片保持附件模型（缩略图 + 灯箱，与 R2 级联清理一致），未改为 `![](url)` 内嵌语法——避免双轨图片来源冲突 |
| 评论图片支持 | 评论也支持插入图片（最多 3 张），方便解答题目时用图片辅助说明（如手写解题步骤拍照上传）。 | P1 | **【已实现】** `community_comments.image_urls`（最多 3 张，复用上传通道与归属校验）；`CommentInput` 点击/Ctrl+V 上传 + 进度条；`CommentItem` 缩略图 + 灯箱；删评论/删帖级联清理 R2 |

### 图片上传技术方案（开发参考）

```
┌─────────────────────────────────────────────┐
│  前端 (PostComposer.vue)                      │
│  ┌──────────┐  ┌──────────┐  ┌───────────┐  │
│  │ 点击上传  │  │ 拖拽上传  │  │ Ctrl+V粘贴│  │
│  └────┬─────┘  └────┬─────┘  └─────┬─────┘  │
│       └──────────────┼──────────────┘        │
│                      ▼                       │
│          前端校验（大小/格式/数量）              │
│                      │                       │
│                      ▼                       │
│    POST /api/community/upload  (裸二进制)      │
└──────────────────────┬──────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────┐
│  Cloudflare Worker                            │
│  ├─ 鉴权 (登录态) + 限流                       │
│  ├─ Magic Bytes 校验 (防止伪造 Content-Type)    │
│  ├─ EXIF 元数据剥离                            │
│  ├─ 存储到 R2 Bucket (zsb-study-images)       │
│  └─ 返回: { id: "16位hex", url: "/api/..." } │
└──────────────────────────────────────────────┘
```

**关键设计决策（已按实际实现更正）**：
- **不复用第三方图床服务**：数据主权归属自身 R2 Bucket（`zsb-study-images`），用户上传的题目截图不经过第三方服务器，符合隐私合规。
- **前端即时预览**：拖拽/粘贴后立即展示本地缩略图 + 上传进度条（`XMLHttpRequest.upload.onprogress`），上传完成后替换为远程 URL，避免用户等待焦虑。
- **隐私保护**：服务端剥离 EXIF/GPS/设备信息（JPEG APP1/COM、PNG eXIf/文本块、WebP EXIF/XMP），防止隐私泄露；删除帖子时同步清理 R2 对象（`deleteUploads`），避免孤儿文件。
- **原设计与实际差异**：原规划"上传时压缩为 WebP（质量 85%）"、"原始文件保留 30 天后自动过期（R2 Object Lifecycle）" **未落地**——当前为剥离元数据后原样存储、永久保留。若需节省存储，可后续补充（P1）。

## 核心增强三：学习兴趣激发

> 设计理念：让社区成为"学习动力加油站"而非"社交消耗时间"。每一个社区互动都在强化学习行为。

### 学习兴趣激发机制

| 功能名称 | 描述 | 优先级 | 实现状态 |
|---------|------|--------|---------|

## 关键设计约束（供开发参考）

1. **治理透明**：所有隐藏/删除/采纳操作必须留痕（`community_moderation_log`）并可对被处理用户发送带原因通知 —— **已落地**（举报处理全链路：留痕 + system 通知告知双方）。
2. **最小惩罚**：管理员操作不扣用户积分；举报不公开举报人；误判可驳回恢复 —— **已落地**（管理员删帖/删评论跳过积分回收；举报人匿名；驳回可恢复）。
3. **复用优先**：积分/管理员体系复用现有 `gamification` 表与 `awardStatements`；通知系统基于已建的 `community_notifications` 表开发。Markdown 渲染复用已有 `markdown-it`，数学公式复用已有 `katex` —— **已落地**（积分复用 `gamification`/`points_log`，服务端流水 refId 带 `srv:` 前缀与全量同步同口径）。
4. **性能**：列表查询沿用游标分页 + 冗余聚合字段（`likes_count` 等），新增表均建必要索引。图片列表页仅加载缩略图（R2 Image Resizing），详情页加载原图 —— **部分落地**（游标分页/冗余计数/索引已建；R2 Image Resizing 缩略图未启用，当前列表直接加载原图首张）。
5. **图片隐私安全**：服务端剥离 EXIF 元数据（GPS 位置、设备信息等），防止用户隐私泄露。上传文件 Magic Bytes 校验，防止 Web Shell 伪装成图片上传 —— **已落地**。
6. **渐进增强**：图片上传功能上线后，纯文本发帖仍完全可用——不强制要求配图，让不同使用习惯的用户都能舒适使用 —— **已落地**。
