# 社区广场模块设计文档

## 一、设计原则

1. **深度复用现有数据模型**：社区内容（打卡动态、学习分享）由已有学习记录、每日总结、成就等自动生成，避免重复录入。
2. **新增表最小化**：只新增帖子、评论、关注、通知等不可复用的社交关系表。
3. **积分体系统一**：社区积分与学习积分合并为同一套 `gamification.points`，社区行为（发帖、获赞）通过同一条 `pointsLog` 流水记录，共享已有的等级系统（青铜→王者）和成就系统。
4. **架构一致**：前端遵循 Vue 3 + Pinia + Tailwind 模式；后端遵循 Cloudflare Worker + D1 + JWT 认证体系；API 与现有 REST 风格保持一致。

---

## 二、与现有功能的衔接设计

| 现有模块 | 社区复用方式 |
|:---|:---|
| **每日总结** (`DailySummary`) | 写完总结后可「一键分享到广场」，自动生成帖子（含心情 emoji、收获/反思文字、当日学习数据摘要） |
| **学习记录** (`StudyRecord`) | 每日首次完成学习后自动生成「打卡动态」卡片（今日科目×时长、刷题数×正确率、番茄钟数），用户选择是否发布 |
| **成就系统** (`Gamification`) | 解锁成就时提示「分享到广场」，生成成就展示帖；已有的 10 个成就定义可同时作为社区勋章 |
| **等级系统** (`LEVELS`) | 社区用户卡片展示当前等级和积分，排行榜复用同一套积分数值 |
| **用户信息** (`Settings.userName`) | 作为社区展示名称；如需头像，后续可扩展 `avatarUrl` 字段（初期用首字母或默认头像） |
| **科目体系** (`Subject`) | 科目名称映射为社区话题标签（#高等数学 #英语），帖子可按科目筛选 |
| **习惯打卡** (`Habit`) | 完成习惯后可选分享到广场，生成简短动态（如「连续 7 天早起晨读 🌅」） |
| **背单词** (`VocabRecord`) | 每日背单词打卡自动生成动态卡片（新词×复习×总计） |
| **番茄钟** (`PomodoroStat`) | 专注时段完成时可生成自夸帖（「刚完成一个番茄钟 🍅 高数第三章导数」） |

## 三、功能模块清单与优先级

### P0 — MVP 核心（首期交付）

| 序号 | 模块 | 说明 |
|:---:|:---|:---|
| 1 | **动态广场** | 社区首页信息流，展示所有用户公开的帖子。按「最新/热门」排序，支持筛选框（全部/关注/按科目标签）。帖子类型：打卡动态、经验分享、成就展示、总结分享。滚动自动加载更多。 |
| 2 | **发帖/分享** | 从现有页面一键生成帖子：①每日总结页的「分享到广场」按钮 ②学习记录保存后弹出「分享打卡」选项 ③成就解锁弹窗的「炫耀一下」按钮 ④习惯打卡后的分享入口。每种来源自动填充帖子预设内容，用户可编辑后发布。 |
| 3 | **评论/回复** | 帖子详情页支持一级评论和嵌套回复（最多二级），支持 @提及用户名，输入框支持 emoji。 |
| 4 | **点赞** | 帖子列表和详情页均可点赞/取消点赞，实时更新计数。点赞通知被赞用户。 |
| 5 | **话题标签** | 预设话题分类与现有科目对应：`#高等数学` `#英语` `#每日打卡` `#升本经验` `#笔记分享` `#心情树洞`。发帖时可多选标签，广场按标签筛选。 |

### P1 — 社交关系（二期）

| 序号 | 模块 | 说明 |
|:---:|:---|:---|
| 6 | **关注/粉丝** | 用户可互相关注，「关注」tab 展示关注用户的动态。用户卡片展示关注数和粉丝数。 |
| 7 | **通知中心** | 顶部导航栏通知图标+未读红点。通知类型：获赞、新评论、被关注、成就解锁提醒。通知列表按时间倒序，支持「全部已读」。 |
| 8 | **学习排行榜** | 多维度排行：①今日学习时长榜 ②本周积分榜 ③连续打卡天数榜 ④累计获赞榜。实时刷新，展示 Top 50。 |

### P2 — 内容深化（三期）

| 序号 | 模块 | 说明 |
|:---:|:---|:---|
| 9 | **经验长文** | 支持 Markdown 编辑的长文帖（备考攻略、学科笔记），复用项目已有的 `markdown-it` + KaTeX 数学公式渲染。含封面图、摘要、阅读量。 |
| 10 | **学习挑战** | 官方/用户发起限时挑战（如「21天数学打卡挑战」「每日一题挑战」），用户报名参与，完成获得额外积分和挑战专属勋章。 |
| 11 | **举报/审核** | 用户可举报不当内容，管理员后台审核（屏蔽帖子、禁言）。首次交付时先做前端举报按钮 + 后端标记字段，管理后台后续补充。 |

### P3 — 深度社交（四期）

| 序号 | 模块 | 说明 |
|:---:|:---|:---|
| 12 | **学习小组** | 用户创建/加入小组（如「2026升本数学冲刺组」），组内有独立动态流、成员列表、小组公告。组内打卡数据汇总。 |
| 13 | **学习搭子匹配** | 按备考目标（考试日期）、学习时段、薄弱科目匹配学习伙伴，双向确认后建立搭子关系。 |
| 14 | **私信** | 用户间一对一私信（文字+图片），简化版即时通讯。 |
| 15 | **资源分享墙** | 用户上传分享学习资料（PDF、笔记），按科目和类型分类浏览下载。复用现有 `Material` 数据模型。 |

## 四、数据模型设计

### 4.1 新增 D1 表（4 张核心表 + 2 张扩展表）

#### 表 1：`community_posts` — 帖子表

```sql
CREATE TABLE community_posts (
  id           TEXT PRIMARY KEY,            -- UUID
  user_id      TEXT NOT NULL,               -- 作者用户 ID（外键 users.id）
  type         TEXT NOT NULL DEFAULT 'share', -- post 类型: 'checkin'(打卡) | 'share'(分享) | 'achievement'(成就) | 'longform'(长文)
  content      TEXT NOT NULL,               -- 帖子正文
  tags         TEXT NOT NULL DEFAULT '[]',   -- JSON 数组: ['#每日打卡', '#高等数学']
  ref_type     TEXT,                        -- 关联源类型: 'summary' | 'record' | 'achievement' | 'habit' | 'vocab'
  ref_id       TEXT,                        -- 关联源 ID（如 summary date、achievement id）
  likes_count  INTEGER NOT NULL DEFAULT 0,  -- 点赞数（冗余聚合，避免 JOIN）
  comments_count INTEGER NOT NULL DEFAULT 0,-- 评论数（冗余聚合）
  is_pinned    INTEGER NOT NULL DEFAULT 0,  -- 是否置顶（管理员功能）
  is_hidden    INTEGER NOT NULL DEFAULT 0,  -- 是否被屏蔽（审核）
  created_at   INTEGER NOT NULL,            -- Unix 时间戳（秒）
  updated_at   INTEGER NOT NULL             -- Unix 时间戳（秒）
);
CREATE INDEX idx_posts_user_id ON community_posts(user_id);
CREATE INDEX idx_posts_created_at ON community_posts(created_at);
CREATE INDEX idx_posts_type ON community_posts(type);
CREATE INDEX idx_posts_tags ON community_posts(tags);
```

#### 表 2：`community_comments` — 评论表

```sql
CREATE TABLE community_comments (
  id           TEXT PRIMARY KEY,            -- UUID
  post_id      TEXT NOT NULL,               -- 所属帖子 ID
  user_id      TEXT NOT NULL,               -- 评论者用户 ID
  parent_id    TEXT,                        -- 父评论 ID（NULL = 一级评论，非 NULL = 回复）
  content      TEXT NOT NULL,               -- 评论内容
  likes_count  INTEGER NOT NULL DEFAULT 0,  -- 点赞数
  is_hidden    INTEGER NOT NULL DEFAULT 0,  -- 是否被屏蔽
  created_at   INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL,
  FOREIGN KEY (post_id) REFERENCES community_posts(id) ON DELETE CASCADE
);
CREATE INDEX idx_comments_post_id ON community_comments(post_id);
CREATE INDEX idx_comments_parent_id ON community_comments(parent_id);
CREATE INDEX idx_comments_created_at ON community_comments(created_at);
```

#### 表 3：`community_likes` — 点赞表

```sql
CREATE TABLE community_likes (
  user_id      TEXT NOT NULL,               -- 点赞用户 ID
  target_type  TEXT NOT NULL,               -- 'post' | 'comment'
  target_id    TEXT NOT NULL,               -- 帖子/评论 ID
  created_at   INTEGER NOT NULL,
  PRIMARY KEY (user_id, target_type, target_id)
);
CREATE INDEX idx_likes_target ON community_likes(target_type, target_id);
```

#### 表 4：`community_follows` — 关注表

```sql
CREATE TABLE community_follows (
  follower_id  TEXT NOT NULL,               -- 关注者用户 ID
  followee_id  TEXT NOT NULL,               -- 被关注者用户 ID
  created_at   INTEGER NOT NULL,
  PRIMARY KEY (follower_id, followee_id)
);
CREATE INDEX idx_follows_followee ON community_follows(followee_id);
CREATE INDEX idx_follows_follower ON community_follows(follower_id);
```

#### 表 5：`community_notifications` — 通知表

```sql
CREATE TABLE community_notifications (
  id           TEXT PRIMARY KEY,            -- UUID
  user_id      TEXT NOT NULL,               -- 接收通知的用户 ID
  type         TEXT NOT NULL,               -- 'like' | 'comment' | 'follow' | 'achievement'
  actor_id     TEXT,                        -- 触发通知的用户 ID（like/comment/follow 时）
  post_id      TEXT,                        -- 关联帖子 ID（like/comment 时）
  comment_id   TEXT,                        -- 关联评论 ID（comment 回复时）
  content      TEXT NOT NULL DEFAULT '',    -- 通知摘要文本（如 "张三 赞了你的帖子"）
  is_read      INTEGER NOT NULL DEFAULT 0,  -- 是否已读
  created_at   INTEGER NOT NULL
);
CREATE INDEX idx_notify_user ON community_notifications(user_id, created_at);
CREATE INDEX idx_notify_unread ON community_notifications(user_id, is_read);
```

#### 表 6：`community_reports` — 举报表（三期）

```sql
CREATE TABLE community_reports (
  id           TEXT PRIMARY KEY,            -- UUID
  reporter_id  TEXT NOT NULL,               -- 举报者用户 ID
  target_type  TEXT NOT NULL,               -- 'post' | 'comment'
  target_id    TEXT NOT NULL,               -- 被举报内容 ID
  reason       TEXT NOT NULL,               -- 举报原因
  status       TEXT NOT NULL DEFAULT 'pending', -- 'pending' | 'resolved' | 'dismissed'
  resolved_by  TEXT,                        -- 处理人
  created_at   INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL
);
```

## 五、API 端点设计

所有社区 API 均需 `Authorization: Bearer <jwt>` 认证，路径前缀 `/api/community`。

### 5.1 帖子

| 方法 | 路径 | 说明 |
|:---|:---|:---|
| `GET` | `/api/community/posts` | 帖子列表。Query: `?sort=latest\|hot`，`?tag=高等数学`，`?type=checkin`，`?following=1`，`?cursor=<id>&limit=20`（游标分页） |
| `GET` | `/api/community/posts/:id` | 帖子详情（含评论列表、当前用户是否点赞） |
| `POST` | `/api/community/posts` | 创建帖子。Body: `{ type, content, tags, refType?, refId? }` |
| `DELETE` | `/api/community/posts/:id` | 删除帖子（仅作者本人） |
| `PUT` | `/api/community/posts/:id/hide` | 管理员隐藏帖子 |

### 5.2 评论

| 方法 | 路径 | 说明 |
|:---|:---|:---|
| `GET` | `/api/community/posts/:id/comments` | 帖子评论列表。Query: `?cursor=<id>&limit=20` |
| `POST` | `/api/community/posts/:id/comments` | 发表评论。Body: `{ content, parentId? }` |
| `DELETE` | `/api/community/comments/:id` | 删除评论（仅作者本人） |

### 5.3 点赞

| 方法 | 路径 | 说明 |
|:---|:---|:---|
| `POST` | `/api/community/likes` | 点赞/取消点赞（toggle）。Body: `{ targetType: 'post'\|'comment', targetId }` |

### 5.4 关注

| 方法 | 路径 | 说明 |
|:---|:---|:---|
| `POST` | `/api/community/follows` | 关注/取消关注。Body: `{ followeeId }` |
| `GET` | `/api/community/users/:id/followers` | 粉丝列表 |
| `GET` | `/api/community/users/:id/following` | 关注列表 |

### 5.5 通知

| 方法 | 路径 | 说明 |
|:---|:---|:---|
| `GET` | `/api/community/notifications` | 通知列表。Query: `?cursor=<id>&limit=20` |
| `PUT` | `/api/community/notifications/read-all` | 全部标记已读 |
| `PUT` | `/api/community/notifications/:id/read` | 单条标记已读 |

### 5.6 排行榜

| 方法 | 路径 | 说明 |
|:---|:---|:---|
| `GET` | `/api/community/leaderboard` | 排行榜。Query: `?type=daily_time\|points\|streak\|likes`，`?limit=50` |

### 5.7 举报（三期）

| 方法 | 路径 | 说明 |
|:---|:---|:---|
| `POST` | `/api/community/reports` | 提交举报。Body: `{ targetType, targetId, reason }` |

## 七、Worker 端实现要点

### 7.1 `worker/src/api/community.ts` 核心逻辑

```
社区 API 模块
├── posts/
│   ├── listPosts(query)      → GET /api/community/posts
│   │   支持 cursor 游标分页、按 tag/type/following 筛选
│   │   按 created_at DESC 排序（最新）
│   │   热门排序：按 (likes_count * 2 + comments_count * 3) / (now - created_at) 衰减
│   ├── getPost(id)           → GET /api/community/posts/:id
│   │   同时返回该帖子的评论树（最多 2 层）
│   │   填充 likedByMe 字段
│   ├── createPost(userId, body) → POST /api/community/posts
│   │   内容校验（长度 1-5000 字符）
│   │   自动记录社区积分 +5
│   │   通知所有关注者
│   └── deletePost(userId, id)   → DELETE /api/community/posts/:id
│       仅作者可删除；级联删除评论和点赞
│
├── comments/
│   ├── listComments(postId)  → GET 评论列表（游标分页）
│   ├── createComment(userId, postId, body) → POST
│   │   更新帖子 comments_count
│   │   记录积分 + 发送通知
│   └── deleteComment(userId, id) → DELETE
│
├── likes/
│   └── toggleLike(userId, body) → POST（幂等 toggle）
│       更新 target 的 likes_count
│       更新用户 gamification 获赞计数
│       发送通知
│
├── follows/
│   ├── toggleFollow(userId, followeeId) → POST
│   └── listFollowers / listFollowing → GET
│
├── notifications/
│   ├── listNotifications(userId) → GET
│   ├── readOne(userId, id)        → PUT
│   └── readAll(userId)            → PUT
│
├── leaderboard/
│   └── getLeaderboard(type) → GET
│       直接使用 SQL 窗口函数排序
│       daily_time: 从 study_records 聚合当日时长
│       points: 从 users gamification JSON 中提取 points
│       streak: 从 users gamification JSON 中提取 streak
│       likes: 从 community_likes 按被点赞用户聚合
│
└── reports/
    └── createReport(userId, body) → POST
```

## 九、风险与注意事项

1. **数据一致性**：点赞计数 `likes_count` 在 `community_posts` 和 `community_comments` 表中冗余存储。点赞/取消点赞时必须同时更新计数，使用 D1 batch 保证原子性。

2. **积分安全**：每日首帖积分只给一次（按日期去重）。获赞积分避免刷分（同一用户对同一帖子只能点赞一次，由 `PRIMARY KEY (user_id, target_type, target_id)` 保证）。

3. **隐私边界**：用户可选择是否将学习数据分享到社区。分享的帖子内容由用户确认后才发布，不自动公开。

4. **图片支持**：首期 MVP 帖子仅支持文字+emoji，暂不上传图片（避免 OSS 依赖和审核压力）。后续可通过 `content` 中的 Markdown 图片语法 + 后端图片代理实现。

5. **D1 性能**：社区表数据增长快（帖子+评论），需要索引覆盖高频查询。`likes_count` 和 `comments_count` 的冗余聚合避免了每次查询的 JOIN 开销。

6. **向后兼容**：新增的 `gamification` 字段（`followingCount` 等）均为可选字段，不影响现有数据的序列化/反序列化。未同步社区数据时这些字段为 `undefined`，前端判断后显示「--」。
